# AGENTS.md — RxAuth AI

Instructions for any AI coding agent working in this repository. Tool-neutral;
`CLAUDE.md` imports this file. Deeper, topic-scoped rules live in `.claude/rules/`.

## What this is

A human-in-the-loop prior-authorization **decision-support** prototype for specialty
pharmacy. It ingests a case's documents, classifies them, extracts cited evidence,
retrieves the right payer-policy *version*, turns policy prose into typed criteria,
matches evidence to criteria, drafts a cited checklist, and gates every claim on its
citations. It prepares a case for a human; it never decides one.

Offline by design: no LLM, no network in the core pipeline. Synthetic data only.

## Commands

```bash
uv sync --extra service --group dev        # full dev env (matches CI)
uv run ruff check . && uv run ruff format --check .
uv run pytest                              # whole suite
uv run pytest tests/test_matching.py -q    # one module
uv run rxauth-train-classifier             # needed once before run-case (artifacts/ is gitignored)
uv run rxauth-run-case data/cases/PA-CASE-001
uv run rxauth-evaluate                     # every layer vs. its threshold ratchet
uv run rxauth-check-reports                # committed reports must reproduce

cd web && npm ci && npm run lint && npm run typecheck && npm test && npm run build
docker compose up --build                  # Postgres + migrate + API + worker + UI on :3000
```

The full CI job order is in `.github/workflows/ci.yml`. The `/regenerate-reports`
skill runs the report sequence.

## Architecture in one paragraph

`workflow.py` owns a 13-node state graph (`workflow.NODES`); `case_assembly.py` owns
the stages it calls; `pipeline.py` assembles the report; `matching.py` is the core;
`groundedness.py` is the citation gate. `models.py` defines every shape and is
imported by everything. **Dependencies run one way**: nothing imports `case_assembly`
or `cli`, and `case_assembly` imports `workflow` lazily. Don't add a cycle. `api.py`
exposes the workflow over FastAPI; `jobs.py`/`worker.py` run cases durably.

## Non-negotiable invariants

1. **Administrative scope.** No code may diagnose, recommend treatment, approve/deny,
   or submit. `await_human_review` is the terminal node; nothing auto-submits.
2. **Five results are real answers.** `SATISFIED`, `NOT_SATISFIED`, `MISSING`,
   `AMBIGUOUS`, `HUMAN_REVIEW_REQUIRED`. Never collapse uncertainty into a guess.
3. **Every claim is cited** (document, page, char span, verbatim quote). Never loosen
   `groundedness.py` to make something pass.
4. **No fabricated metrics.** `reports/` is regenerated by its command, never edited.
   Gold sets (`data/*_gold.jsonl`) are never edited to make a benchmark pass.
   `evaluation_suite.py` thresholds only move up, or move down in a deliberate,
   explained diff.
5. **PA-required comes from input** (`case.json`/manifest), never inferred from policy text.
6. **Synthetic data only; PHI-safe logging.** Never log quoted spans outside
   `environment=local`. Never add real patient data.
7. **Tenant isolation.** Every persistence read/write takes `organization_id`; another
   org's resource is a 404, never a 403.
8. **Version what produces a result.** Bump the module's `*_VERSION` constant (e.g.
   `MATCHER_VERSION`, `EXTRACTOR_VERSION`) when its behaviour changes.

## Working style

- Before editing, state which files change, what changes, and the blast radius (use
  the table in `docs/code-walkthrough.md`).
- Match surrounding code: module docstrings explain *why*; comments are sparse and
  explain decisions, not syntax.
- A behaviour change normally means: code + test + version bump + regenerated report.
- Development is on Windows; CI runs Ubuntu and Windows. Use `pathlib`, explicit
  `encoding="utf-8"`, and no shell-specific assumptions in Python.
